# 機能設計書

Waders の機能と業務ルール（画面に依らない振る舞い）を定める。実装（`src/server/domain/`・`src/server/application/`・`src/server/presentation/`）と常に一致させる。画面は [画面設計書](画面設計書.md)、保存するデータは [データ設計書](データ設計書.md) を参照。

## 2. 業務ルール

日・月の判定はすべて日本時間（Asia/Tokyo）の暦で行う。現在時刻はアプリケーション層の `Clock` から受け取る。

| --- | --- | --- |
| BR-01 | **発売月の超過**: 発売月の翌月 1 日 0:00 になったら超過とする（例: 発売月 2026-11 は 2026-12-01 0:00 から超過） | `isProductArchived` |
| BR-02 | **予約済の自動遷移**: 発売月を超過したら購入済にし、延期の確認待ちにする。受注期限は見ない | `determineAutomaticTransition` |

| BR-04 | **購入済・未購入**: 自動では変えない（手で購入済にした商品は延期の確認の対象外） | `determineAutomaticTransition` |
| BR-05 | **アーカイブ**: 発売月が当月より前の商品は、ステータスにかかわらずアーカイブとする。アーカイブかどうかは保存せず、その都度求める | `isProductArchived`・`splitProductsByArchive` |

| BR-37 | **ステータスだけの変更**（詳細画面のプルダウン）: ステータスと、指定されたときだけキャンセル可否を変える（省いた場合は今のまま）。ステータスもキャンセル可否も今と同じなら何もしない（更新日時も履歴も変えない）。ステータスが変わった場合は利用者の操作として変更履歴に記録する。アーカイブされた商品も変えられる（issue #52） | `changeProductStatus` |
| BR-39 | **受注期限を過ぎた商品を検討中にする**: 利用者の操作で保存する商品（登録・編集・ステータスの変更・リストに戻すなど）が検討中で、受注期限を超過している（日本時間の受注期限の翌日 0:00 を迎えた）場合は、受注期限を消して保存する。受注期限が残っていると、自動遷移ですぐに未購入に戻るため（BR-03）。自動遷移では消さない。変更履歴には記録しない（履歴はステータスと発売月だけ）（issue #60） | `clearPassedOrderDeadlineOfConsidering`（productStatusTransition.ts） |

## 3. F-02 ステータスの自動遷移

- 判定の時期: 商品の一覧を取得するたび（`GET /api/products`）と、サーバーの起動時
- 遷移した場合は、変更履歴に種類「自動遷移」（`automatic`）、変更日時は判定した時刻で記録する
- 遷移の対象がなければ何も記録しない（何度一覧を取得しても履歴は増えない）
- 1 商品の遷移（ステータスの更新・履歴・延期の確認待ち）は 1 つのトランザクションで行う

```
            発売月を超過（BR-02）
  予約済 ─────────────────────────→ 購入済 ＋ 延期の確認待ち
            受注期限の翌日 or 発売月を超過（BR-03）
  検討中 ─────────────────────────→ 未購入
```

## 4. F-04 リストに戻す

1. 商品がアーカイブされていなければ拒否する（409 `PRODUCT_NOT_ARCHIVED`）
2. 新しい発売月が当月より前なら拒否する（400 `RELEASE_MONTH_IN_PAST`。BR-07）
3. ステータスを BR-06 で求め、発売月を新しい月にし、延期の確認待ちを外す。変更は利用者の操作（`user`）として記録する

## 5. F-05 延期の確認

| 回答 | 結果 |
| --- | --- |
| 届いた（`arrived`） | 購入済のまま（アーカイブに残る） |
| 延期された（`postponed`） | 新しい発売月（当月以降。BR-07）で予約済にする（リストに戻る） |
| 買わなかった（`notPurchased`） | 未購入にする（アーカイブに残る） |

- いずれの回答でも延期の確認待ちを外す。変更は利用者の操作（`user`）として記録する
- 確認待ちでない商品への回答は拒否する（409 `DELIVERY_CONFIRMATION_NOT_PENDING`）
- 画面は回答した商品だけを送る。回答しなかった商品は確認待ちのまま残り、次に開いたときにまた確かめる

## 7. F-08 認証

- **設定**: 設定ファイルの `authenticationEnabled`（環境変数 `WADERS_AUTHENTICATION_ENABLED` が優先。`true`・`false` のみ）。ひな形では `false`（issue #33）。項目がない既存の設定ファイルは有効として扱う（安全側に倒す）
- **パスワードの保存**: `crypto.scrypt`（N = 16384、r = 8、p = 1、ソルト 16 バイト、長さ 32 バイト）のハッシュ値を、パラメーターとソルトと一緒に保存する。比較は `timingSafeEqual`
- **ログインした状態**: 乱数 32 バイトの値を Cookie `waders_session` に入れる（`HttpOnly`・`SameSite=Strict`・`Path` は `basePath`（`""` なら `/`。BR-30）・`Max-Age` 30日）。DB にはその値の SHA-256 だけを保存する。HTTPS の仕組みがないため `Secure` は付けない
- **CSRF**: 状態を変えるリクエスト（ログイン・ログアウトを含む）は `Content-Type: application/json` を必須にする（既存の決まり）。Cookie は `SameSite=Strict`
- **同時のログイン**: ログインの試行は1つずつ順に処理する（同時に送られた試行で BR-21 の回数をすり抜けさせない）
- **接続元**（BR-21。issue #36）: TCP の接続元（`request.socket.remoteAddress`）を使う。リバースプロキシを使わないため、偽装できる `X-Forwarded-For` や Express の `trust proxy` は使わない。接続元が分からない場合（接続が切れた後など）は、分からないものどうしを1つの接続元として数える
- **失敗の記録の片付け**（BR-21。issue #36）: 制限が解けた記録と、制限せずに最後の失敗から24時間たった記録は、ログインの試行のたびに捨てる（失敗の間が24時間以上空いた場合は、1回目から数え直す）。記録する接続元は1000までとし、上限に達した後に新しく失敗した接続元は、まとめて1つの接続元として数える（記録を追い出すと、追い出された接続元が制限をすり抜けられるため。持ち主の接続元にすでに記録があれば、その記録で判定する）

## 8. F-10 外部のサイトからの不正な接続の防止

- **目的**: 攻撃者のドメインの名前解決を、ページを開かせた後で Waders の IP アドレスに切り替える（DNS リバインディング）と、ブラウザからは同じオリジンへの通信に見えるため、`Content-Type: application/json` の必須（CSRF 対策）や CORS では防げない。ブラウザはこのとき攻撃者のドメインを Host に付けるため、Host を許した名前に限って防ぐ（BR-29）
- **設定**: `settings.json` の `allowedHosts`（ホスト名の配列。小文字にそろえる。ポート・URL・空白を含む値は設定の誤りとして起動を止める）と `hostValidationEnabled`（真偽値）。ひな形は `[]` と `true`。項目がなければ追加の名前なし・有効（安全側に倒す）。環境変数では切り替えない
- **順序**: セキュリティヘッダーを付けた直後、API と画面のファイルの配信より前に確かめる（403 の応答にも CSP を付ける）
- **開発時**: Vite のプロキシは `changeOrigin: false` で Host を `localhost:5173` のまま送る（vite.config.ts）。画面の Origin も `http://localhost:5173` のため、追加の設定なしで使える（`changeOrigin` を有効にすると Host がサーバーのポートに書き換わり、Origin と一致せず 403 になる）
- **無効にする場合**: リバースプロキシなどでインターネットに公開し、宛先の名前を前もって決められない場合。無効にしても `Content-Type` の確認（415）は残る

## 9. F-11 画面と API を置くパス

- **目的**: Raspberry Pi で `http://raspberrypi.local:8080/waders/` から開けるようにする。ポート 80 は Homebridge のイメージの nginx が使っていて、その設定は変えないため、ポートは残してパスだけを変える（issue #39）
- **設定**: `settings.json` の `basePath`。`""` か、`/` で始まる区切りの並び（英数字と `-`・`_`・`.`・`~`。`.`・`..` だけの区切り、末尾の `/`、`/` だけは不可）。誤った値は設定の誤りとして起動を止める。ひな形は `"/waders"`。項目がなければ `/waders`（更新するだけで新しい URL になる）。環境変数では切り替えない
- **サーバー**: Host・Origin の確認（BR-29）の後に `/` と `<basePath>` を転送し、画面と API をまとめたルーターを `<basePath>` に置く。画面の入り口（index.html）は、区切り `api` を含まない URL にだけ返す（パスの外の API の URL を画面と取り違えないため）
- **転送**: 302 にする。301 だとブラウザが覚え、設定を変えた後も古い転送が残るため
- **画面**: ビルド（Vite）は `base: './'` で、部品のファイルを相対パスで読み込む。API は `new URL('./api/...', document.baseURI)` で呼び先を決める。そのため、画面を作り直さずに `basePath` だけで変わる。画面の URL は1段（`/waders/archive` など）までを想定する
- **開発時**: 画面は今までどおり `http://localhost:5173/` で開く。Vite のプロキシは `/api` を、サーバーの `<basePath>/api` へ書き換えて転送する（vite.config.ts）

## 10. F-12 商品の画像

- **画面での準備**: 選んだ画像を `createImageBitmap`（写真の向きを反映）で読み、縦横の比を保って長い辺を 800px 以内に縮め（大きくはしない）、白の背景に重ねて JPEG（画質 0.85）にする。写真の位置情報などはこのとき消える。読めないファイルは欄の下に知らせ、送らない
- **貼り付け**（#45）: モーダルの `paste` イベントで、貼り付けの中身（`clipboardData` の `items`、なければ `files`）から最初の画像のファイルを取り、選んだファイルと同じく準備する。`navigator.clipboard.read()` は安全な接続（HTTPS・localhost）でしか使えないため使わない。iPhone で長押しの「ペースト」を出すため、画像の欄に編集できる要素（`contenteditable`。文字の入力は止める）の貼り付け欄を置く
- **プレビュー**: CSP で `data:`・`blob:` の画像を禁止しているため、選んだ画像は canvas に描く。編集では今の画像を API から読んで表示する
- **送り方**: 本文は JSON の `{ data }`（base64）。状態を変えるリクエストの `Content-Type: application/json` の必須（CSRF 対策）をそのまま使うため、multipart にはしない。本文の大きさの上限は API 全体で 100kb、画像を付ける API だけ 3MB（2MB の画像の base64 が入る大きさ）
- **保存先**: データのフォルダの `images`（所有者だけが使える 0700。最初の保存のときに作る）。ファイルは 0600。DB には商品ごとにファイルの名前だけを記録し、DB の CHECK 制約でも保存した形（UUID と拡張子）の名前に限る（フォルダの外を指さないため）
- **配信**: 画像の応答にもすべての応答と同じセキュリティヘッダー（`default-src 'none'` の CSP・`nosniff`）を付ける。認証が有効なときはログインを求める。`imageUrl` の版が今の画像と同じなら長く覚えさせ（`private, max-age=31536000, immutable`）、版がない・古い URL は毎回確かめさせる（`private, no-cache`）
- **表示**: カードとリストでは切らずに枠の中に収める（`object-fit: contain`）。画像を読み込めなかった場合は共通のアイコンにする（画像を付け直して URL が変われば、読み込み直す）

## 11. F-13 カード画像の取得

- **取りに行く処理**: ページを GET し（200 かつ `text/html` のときだけ）、先頭の 1MB から `<meta>` の `og:image`（`og:image:url`・`og:image:secure_url` を含む）、なければ `twitter:image` の URL を取り出す。相対パスはページ（リダイレクトの後の URL）を基準にし、文字参照を戻す。その画像を GET し、200 かつ 2MB 以内で、中身が JPEG・PNG・WebP のときだけ使う
- **アドレスの確かめ方**: 名前を引く処理を差し替え、引いたすべてのアドレスが接続してよいときだけ、そのアドレスに接続する（確かめた後に名前を引き直さないため、DNS リバインディングで向き先を変えられない）。URL に IP アドレスが直接書かれている場合も確かめる。圧縮しない形（`Accept-Encoding: identity`）で受け取り、読んだ大きさで止める。`User-Agent` は `Mozilla/5.0 (compatible; Waders)`
- **保存**: アップロードした画像と同じフォルダ（`images`）に乱数の名前で保存し、DB の `card_image_file_name` に記録する（アップロードした画像とは別。アップロードした画像を消すとカード画像を表示する）
- **取得中の印**: 取りに行っている商品の ID は、サーバーのメモリにだけ持つ（再起動すると消える。その場合は、次に編集して保存したときに取りに行く）。一覧の `cardImagePending` で示す
- **画面**: 保存したらモーダルをすぐに閉じる。一覧に `cardImagePending` の商品があれば 2 秒ごとに読み直し、なくなったら止める。取りに行ったまま終わらなくても、15 回（30 秒）であきらめる（保存し直すと数え直す）。アーカイブの画面は読み直さない（URL を変えて保存した直後は、開き直せば表示される）
- **止めるとき**: サーバーを止めるときは、取りに行っている途中のもの（長くても 10 秒）が終わるのを待ってから DB を閉じる
- **取れないサイト**: Amazon など、自動の取得を断るサイト・JavaScript でページを作るサイトでは取れない。取り直しのボタンは置かない（URL を入れ直すか、画像をアップロードする）
- **保存の前のプレビュー**（#51。BR-36）: モーダルが `POST /api/products/card-image-preview` を呼び、サーバーは保存の後と同じ取得の処理（`createCardImageFetcher`）で取って、大きさ（2MB）と中身の形式を確かめてから base64 で返す。取れない・失敗した場合もエラーにせず `cardImage: null` を返す。画面は受け取った画像を `createImageBitmap` で読み、選んだ画像と同じく長い辺 800px 以内に縮めて canvas に描く（CSP で `data:`・`blob:` の画像を禁止しているため。Blob は URL にせず直接読む）。取った結果は、モーダルを開いている間 URL ごとに覚え、同じ URL では取り直さない（通信の失敗は覚えない）
- **プレビューの画像を保存で使い回さない**: プレビューで取った画像を保存のときに送ると、アップロードした画像として扱われ、URL を変えたときにカード画像に置き換わらなくなるため。保存の後はサーバーがもう一度取りに行く（同じページを 2 回取ることになる）

## 12. F-14 商品の詳細（#52）

- **開くとき**: 一覧（SCR-01）とアーカイブ（SCR-04）でカードを押したときに、商品の詳細（SCR-09）を開く。編集のモーダルは詳細の「編集」から開き、保存・キャンセルの後は一覧に戻る
- **金額**: 最終的な金額 = 金額＋送料・手数料・交通費（見込）・その他費用 − 値引き（0 円未満にはしない。見出しの合計（BR-25）と同じ考え方）。値がない・0 円の費用と値引きは内訳に出さない（`describeProductAmount`）
- **項目の出し入れ**: 編集のモーダルと同じ決まり（BR-24）で、カテゴリーで有効な項目と値が保存されている項目を出す（`determineVisibleCategoryFields`）。値がない項目と、金額が未入力の場合は「－」と示し、読み上げでは「未入力」と伝える（`role="img"`・`aria-label="未入力"`。#63）
- **ステータスの変更**: プルダウンの「予約済」は `{ status: 'reserved', cancelable: false }`、「予約済（キャンセル可）」は `{ status: 'reserved', cancelable: true }`、それ以外は `{ status }` だけを送る（キャンセル可否は今のまま）。サーバーは BR-37 の決まりで変える。詳細は開いたまま、変えた商品で表示を更新し、一覧を読み込み直す
- **削除**: 編集のモーダルと同じ確認（SCR-03）を出し、`DELETE /api/products/:productId` を送る
