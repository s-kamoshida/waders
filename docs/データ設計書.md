# データ設計書

Waders が保存するデータの形を定める。実装（`src/server/infrastructure/sqliteProductRepository.ts`・`src/shared/productContract.ts`）と常に一致させる。

## 1. 保存先

すべてデータのフォルダ（既定は起動したフォルダの `data`。環境変数 `WADERS_DATA_DIRECTORY` で変更可）に置く。ファイルは所有者のみ読み書き可（0600）とする。

| ファイル | 内容 | 作成のタイミング |
| --- | --- | --- |
| `settings.json` | 設定（ポート・認証の有効・無効など） | 初回起動時に `config/settings.example.json` から作成 |
| `waders.sqlite` | 商品・変更履歴・延期の確認待ち・認証のアカウントとログインした状態の DB（SQLite） | 初回起動時に作成し、スキーマを移行する |
| `categories.json` | カテゴリーの定義（正本。手で編集してよい）（#10） | 初回起動時に `config/categories.example.json` から作成 |
| `images/` | 商品の画像のファイル（アップロードした画像と、購入先のページから取ったカード画像。フォルダは所有者のみ使える 0700）。名前は乱数の UUID と形式の拡張子（`.jpg`・`.png`・`.webp`）（#41・#42） | 最初に画像を付けた・取ったときに作成 |

SQLite は Node.js 標準の `node:sqlite` で扱う。

## 2. 値の形式

入力の検証は `src/shared/productContract.ts` の Zod スキーマに一本化し、同じルールを DB の CHECK 制約にも付ける（検証をすり抜けた値を最後に拒否する）。

| 項目 | 形式 | 範囲・制約 |
| --- | --- | --- |
| 商品名 | 文字列 | 前後の空白を除いて 1〜200 文字 |
| 発売月 | `YYYY-MM`（例: `2026-11`） | 月は 01〜12 |
| ステータス | `considering`（検討中）・`reserved`（予約済）・`purchased`（購入済）・`unpurchased`（未購入）・`canceled`（キャンセル。版数 10 で追加。#57） | 初期値は `considering` |
| キャンセル可否 | 真偽値（DB では 0・1） | 既定は不可 |
| 金額・送料 | 円単位の整数 | 0〜9,999,999。未入力は null |
| 受注期限 | `YYYY-MM-DD`（日本時間の日付） | 存在する日付。その日の終わり（23:59）までを期限内とする。未入力は null |
| URL | 文字列 | `http://`・`https://` のみ、2,048 文字以内。未入力は null |
| カテゴリーの ID | 文字列 | 1〜100 文字。未設定は null。定義にある ID だけを新たに設定できる（#10） |
| カテゴリー名 | 文字列 | 前後の空白を除いて 1〜50 文字。商品には設定したときの名前を保存する（#10） |
| メーカー | 文字列 | 前後の空白を除いて 1〜100 文字。未入力は null（#18） |
| 備考 | 文字列（複数行） | 前後の空白を除いて 1〜1,000 文字。途中の改行は残す。未入力は null（#18） |
| 場所 | 文字列 | 前後の空白を除いて 1〜100 文字。未入力は null（#26） |
| 手数料・交通費（見込）・その他費用 | 円単位の整数 | 0〜9,999,999（金額と同じ）。未入力は null（#26） |
| 値引き | 円単位の整数 | 0〜9,999,999（金額と同じ）。未入力は null（値引きなし）。金額があり、金額・送料・手数料・交通費（見込）・その他費用の合計以下に限る（[機能設計書](機能設計書.md) BR-35。DB は範囲だけを CHECK で確かめる）（#50） |
| 開催日時・終了日時 | UTC の ISO 8601（`2026-11-20T09:00:00.000Z` の形） | 画面では日本時間で分まで入力する。終了日時は開催日時より前にしない（同じ時刻はよい）。片方だけもよい。未入力は null（PR #30） |
| 日時（登録・更新・変更） | UTC の ISO 8601 文字列 | — |

## 3. テーブル

### 3.1 products（商品）

| 列 | 型 | NULL | 制約・説明 |
| --- | --- | --- | --- |
| `id` | TEXT | 不可 | 主キー（UUID） |
| `name` | TEXT | 不可 | 商品名 |
| `release_month` | TEXT | 不可 | 発売月 |
| `status` | TEXT | 不可 | ステータス。CHECK で値の一覧（2 章）だけを許す（`canceled` は版数 10 から。#57） |
| `cancelable` | INTEGER | 不可 | キャンセル可否（0・1） |
| `price` | INTEGER | 可 | 金額（円・税込） |
| `shipping_fee` | INTEGER | 可 | 送料（円・税込） |
| `order_deadline` | TEXT | 可 | 受注期限 |
| `url` | TEXT | 可 | 購入先の URL |
| `category` | TEXT | 可 | カテゴリーを設定したときのカテゴリー名（定義から消えた場合に示すため） |
| `category_id` | TEXT | 可 | カテゴリーの ID（版数 4 で追加。#10）。`category` と両方あるか両方ないかのどちらか（トリガーで確かめる） |
| `maker` | TEXT | 可 | メーカー（版数 3 で追加。#18） |
| `note` | TEXT | 可 | 備考（版数 3 で追加。#18） |
| `location` | TEXT | 可 | 場所（版数 6 で追加。#26） |
| `handling_fee` | INTEGER | 可 | 手数料（円。版数 6 で追加。#26） |
| `travel_expense` | INTEGER | 可 | 交通費（見込）（円。版数 6 で追加。#26） |
| `other_expense` | INTEGER | 可 | その他費用（円。名前はカテゴリーの定義に持つ。版数 6 で追加。#26・#27） |
| `event_starts_at` | TEXT | 可 | 開催日時（UTC の ISO 8601。版数 6 で追加。PR #30） |
| `event_ends_at` | TEXT | 可 | 終了日時（UTC の ISO 8601。`event_starts_at` より前にしない（CHECK）。版数 6 で追加。PR #30） |
| `uploaded_image_file_name` | TEXT | 可 | 付けた画像のファイルの名前（`images/` の中。UUID と `.jpg`・`.png`・`.webp` の形だけ許す（CHECK）。画像がなければ NULL。付けても `updated_at` は変えない。版数 7 で追加。#41） |
| `card_image_file_name` | TEXT | 可 | 購入先のページから取ったカード画像のファイルの名前（`images/` の中。形は `uploaded_image_file_name` と同じ（CHECK）。なければ NULL。`updated_at` は変えない。版数 8 で追加。#42） |
| `discount` | INTEGER | 可 | 値引き（ポイント・クーポンなどの総額。円）。0〜9,999,999（CHECK）。値引きなしは NULL（版数 9 で追加。#50） |
| `created_at` | TEXT | 不可 | 登録日時。一覧はこの順（同時刻は登録した順）に返す |
| `updated_at` | TEXT | 不可 | 更新日時 |

### 3.2 product_history（変更履歴）

ステータスと発売月の推移を記録する。アーカイブから復帰する際に、自動遷移の前のステータスを求めるために使う。

| 列 | 型 | NULL | 制約・説明 |
| --- | --- | --- | --- |
| `id` | INTEGER | 不可 | 主キー（記録した順に増える） |
| `product_id` | TEXT | 不可 | 商品の ID。商品を削除すると履歴も削除する（ON DELETE CASCADE） |
| `changed_at` | TEXT | 不可 | 変更日時 |
| `change_kind` | TEXT | 不可 | `user`（利用者の操作）・`automatic`（自動遷移） |
| `field` | TEXT | 不可 | `status`・`release_month` |
| `value_before` | TEXT | 可 | 変更前の値。登録時は null |
| `value_after` | TEXT | 不可 | 変更後の値 |

記録の規則:

- 登録時: 登録日時に、ステータス → 発売月の順で初期値を記録する（変更前は null、種類は `user`）
- 更新時: ステータス・発売月が変わった場合だけ、ステータス → 発売月の順で記録する。それ以外の項目（メーカー・備考・場所・費用・開催日時を含む）の変更は記録しない
- 履歴は `id` の順（記録した順）に返す
- ステータスの自動遷移は種類を `automatic` として記録する。リストに戻す・延期の確認への回答は `user` として記録する

### 3.3 delivery_confirmations（延期の確認待ち）

予約済から自動で購入済になり、延期の確認（届いたかどうか）を待っている商品（#9）。アーカイブかどうかは発売月から求めるため保存しない。

| 列 | 型 | NULL | 制約・説明 |
| --- | --- | --- | --- |
| `product_id` | TEXT | 不可 | 主キー。商品の ID。商品を削除すると一緒に削除する（ON DELETE CASCADE） |

記録の規則（[機能設計書](機能設計書.md) BR-02・BR-05）:

- 予約済から購入済に自動遷移したときに追加する（すでにあれば何もしない）
- 延期の確認に回答したとき、リストに戻したとき、編集でステータスを変えたとき、詳細画面のプルダウンでキャンセルにしたとき（#57。BR-38）に削除する

### 3.4 account（認証のアカウント。#11）

アカウントは1つだけ（`id` は常に 1）。パスワードは平文で保存しない。

| 列 | 型 | NULL | 制約・説明 |
| --- | --- | --- | --- |
| `id` | INTEGER | 不可 | 主キー。`1` だけ（CHECK） |
| `login_id` | TEXT | 不可 | ID（前後の空白を除いたもの。1〜50 文字） |
| `password_hash` | TEXT | 不可 | `scrypt$N$r$p$ソルト$ハッシュ値`（ソルトとハッシュ値は base64）。`scrypt$` で始まる（CHECK） |
| `created_at` | TEXT | 不可 | 作成した日時（UTC の ISO 8601） |

### 3.5 sessions（ログインした状態。#11）

Cookie の値そのものは保存しない（DB が漏れてもログインした状態を使われないようにする）。

| 列 | 型 | NULL | 制約・説明 |
| --- | --- | --- | --- |
| `token_hash` | TEXT | 不可 | 主キー。Cookie の値の SHA-256（16 進数 64 文字） |
| `created_at` | TEXT | 不可 | ログインした日時（UTC の ISO 8601） |
| `last_used_at` | TEXT | 不可 | 最後に使った日時。ここから 30 日たつと使えない（[機能設計書](機能設計書.md) BR-20） |

- ログアウトしたときに削除する。期限切れの行は、使おうとしたときと、新しくログインしたときに削除する
- `npm run reset-account` でアカウントと一緒にすべて削除する（BR-23）
- ログインの失敗の回数（BR-21）は保存しない（メモリに持つ）

## 4. スキーマの版数と移行

スキーマの版数は SQLite の `PRAGMA user_version` で管理する。移行は `SCHEMA_MIGRATIONS` の要素として定義し、**既存の要素は書き換えず、変更は末尾に追加する**（利用者の既存の DB が壊れるため）。

| 版数 | 内容 | issue |
| --- | --- | --- |
| 1 | `products`・`product_history` を作成 | #7 |
| 2 | `delivery_confirmations` を作成（既存の商品と履歴はそのまま。確認待ちは空） | #9 |
| 3 | `products` に `maker`・`note` を追加（既存の商品は未入力） | #18 |
| 4 | `products` に `category_id` を追加。カテゴリー名だけを持つ既存の商品は ID を `legacy:名前` にする（定義にないカテゴリーとして扱う）。ID と名前の対応を確かめるトリガーを追加 | #10 |
| 5 | `account`・`sessions` を作成（既存の商品はそのまま。アカウントはない状態になる） | #11 |
| 6 | `products` に `location`・`handling_fee`・`travel_expense`・`other_expense`・`event_starts_at`・`event_ends_at` を追加（既存の商品は未入力）。範囲・日時の形式・終了日時が開催日時より前でないことを CHECK で確かめる | #26・#27 |
| 7 | `products` に `uploaded_image_file_name` を追加（既存の商品は画像なし） | #41 |
| 8 | `products` に `card_image_file_name` を追加（既存の商品はカード画像なし） | #42 |
| 9 | `products` に `discount` を追加（既存の商品は値引きなし）。0〜9,999,999 を CHECK で確かめる | #50 |
| 10 | `status` の CHECK に `canceled` を加えるため、`products` を作り直す（SQLite は CHECK を変えられないため）。新しい表を作り、すべての列と `rowid`（同時刻の並び）を写し、古い表を消して名前を変え、カテゴリーの組のトリガーを作り直す。列・ほかの制約・`STRICT` は版数 9 と同じ。既存の商品・変更履歴・延期の確認待ちはそのまま | #57 |

- 版数 1 の `status` の CHECK は、当時の 4 つの値に固定している（以前は今の値の一覧から作っていたため、一覧に値を加えると古い移行の SQL が変わってしまう）。値を加えるときは、版数 10 のように表を作り直す移行を末尾に足す
- 移行の間は外部キーを止める（表を消したときに、変更履歴・延期の確認待ちが `ON DELETE CASCADE` で消えないようにするため。外部キーの切り替えはトランザクションの外でしかできない）。各移行の最後に `PRAGMA foreign_key_check` で整合を確かめ、崩れていれば取り消して起動を止める。移行が終わったら外部キーを戻す
- 版数 10 の移行は表を作り直すため、デプロイの前に DB のバックアップを取る

DB の版数がアプリの版数より新しい場合は、起動を止める（古いアプリで新しい DB を壊さないため）。

## 5. カテゴリーの定義のファイル（categories.json。#10）

カテゴリーの定義の正本。デプロイする人が手で編集できる。ひな形は [config/categories.example.json](../config/categories.example.json) で、初回起動時のコピー元にだけ使う。

```json
{
  "version": 1,
  "categories": [
    { "id": "k3f9x2ab", "name": "スケールフィギュア" },
    { "name": "プラモデル" },
    { "id": "t8w4n1ce", "name": "電子チケット", "fields": ["location", "eventPeriod", "handlingFee", "travelExpense", "otherExpense"], "otherExpenseLabel": "ドリンク代" }
  ]
}
```

| 項目 | 形式 | 説明 |
| --- | --- | --- |
| `version` | `1` | 形式の版 |
| `categories` | 配列 | 並び順が、絞り込み・プルダウンでの表示順 |
| `categories[].id` | 文字列（1〜100 文字） | 省略できる。省略されたカテゴリーには、アプリが読み込んだときに英小文字と数字 8 文字の ID を付けて書き戻す（ほかの内容と並び順は変えない） |
| `categories[].name` | 文字列（前後の空白を除いて 1〜50 文字） | カテゴリー名 |
| `categories[].fields` | 文字列の配列 | 省略できる。入力する項目の名前（`shippingFee`・`maker`・`orderDeadline`・`cancelable`・`location`・`eventPeriod`（開催日時と終了日時）・`handlingFee`・`travelExpense`・`otherExpense`）。順は問わず、アプリはこの順で扱う。省略したカテゴリーは `shippingFee`・`maker`・`orderDeadline`・`cancelable` とする（#27） |
| `categories[].otherExpenseLabel` | 文字列（前後の空白を除いて 1〜20 文字） | 省略できる。「その他費用」の名前。省略したカテゴリーは「その他費用」（#27） |

- 読み込むたびに検証する。JSON として読めない・形式に誤りがある・名前や ID が重複している場合は誤りとし、ファイルは書き換えない
- 書き込みは、同じフォルダの一時ファイルに書いてから置き換える（0600）
- 形式の版は 1 のまま。`fields`・`otherExpenseLabel` は省略できる項目として加えたため、今までの定義のファイルはそのまま読め、読み替え（書き換え）はしない（#27）
- `fields` に知らない名前（常に入力する `price` などを含む）がある、配列でない、`otherExpenseLabel` が形式に合わない場合は誤りとする
- アプリが書き込むのは、ID を付けるときと、画面（SCR-07）でカテゴリーを追加・改名・削除したとき、入力する項目・「その他費用」の名前を変えたとき（変えた項目だけを反映し、項目を変えたカテゴリーには `fields` をすべて書く。名前を既定に戻すと `otherExpenseLabel` を取り除く）。そのたびに最新のファイルを読み直して変更し、手で書かれたほかの項目は残す（#10）
- 商品とは ID で対応する。手で名前を変えても ID が同じなら商品は新しい名前で表示される。手で消した ID の商品は、最後に保存した名前で「（定義にない）」と示す
