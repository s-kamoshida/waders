# データ設計書

Waders が保存するデータの形を定める。実装（`src/server/infrastructure/sqliteProductRepository.ts`・`src/shared/productContract.ts`）と常に一致させる。

## 1. 保存先

すべてデータのフォルダ（既定は起動したフォルダの `data`。環境変数 `WADERS_DATA_DIRECTORY` で変更可）に置く。ファイルは所有者のみ読み書き可（0600）とする。

| ファイル | 内容 | 作成のタイミング |
| --- | --- | --- |
| `settings.json` | 設定（ポートなど） | 初回起動時に `config/settings.example.json` から作成 |
| `waders.sqlite` | 商品・変更履歴・延期の確認待ちの DB（SQLite） | 初回起動時に作成し、スキーマを移行する |

SQLite は Node.js 標準の `node:sqlite` で扱う。

## 2. 値の形式

入力の検証は `src/shared/productContract.ts` の Zod スキーマに一本化し、同じルールを DB の CHECK 制約にも付ける（検証をすり抜けた値を最後に拒否する）。

| 項目 | 形式 | 範囲・制約 |
| --- | --- | --- |
| 商品名 | 文字列 | 前後の空白を除いて 1〜200 文字 |
| 発売月 | `YYYY-MM`（例: `2026-11`） | 月は 01〜12 |
| ステータス | `considering`（検討中）・`reserved`（予約済）・`purchased`（購入済）・`unpurchased`（未購入） | 初期値は `considering` |
| キャンセル可否 | 真偽値（DB では 0・1） | 既定は不可 |
| 金額・送料 | 円単位の整数 | 0〜9,999,999。未入力は null |
| 受注期限 | `YYYY-MM-DD`（日本時間の日付） | 存在する日付。その日の終わり（23:59）までを期限内とする。未入力は null |
| URL | 文字列 | `http://`・`https://` のみ、2,048 文字以内。未入力は null |
| カテゴリー | 文字列 | 1〜50 文字。未入力は null（カテゴリーの定義との対応は #10 で定める） |
| メーカー | 文字列 | 前後の空白を除いて 1〜100 文字。未入力は null（#18） |
| 備考 | 文字列（複数行） | 前後の空白を除いて 1〜1,000 文字。途中の改行は残す。未入力は null（#18） |
| 日時（登録・更新・変更） | UTC の ISO 8601 文字列 | — |

## 3. テーブル

### 3.1 products（商品）

| 列 | 型 | NULL | 制約・説明 |
| --- | --- | --- | --- |
| `id` | TEXT | 不可 | 主キー（UUID） |
| `name` | TEXT | 不可 | 商品名 |
| `release_month` | TEXT | 不可 | 発売月 |
| `status` | TEXT | 不可 | ステータス |
| `cancelable` | INTEGER | 不可 | キャンセル可否（0・1） |
| `price` | INTEGER | 可 | 金額（円・税込） |
| `shipping_fee` | INTEGER | 可 | 送料（円・税込） |
| `order_deadline` | TEXT | 可 | 受注期限 |
| `url` | TEXT | 可 | 購入先の URL |
| `category` | TEXT | 可 | カテゴリー名 |
| `maker` | TEXT | 可 | メーカー（版数 3 で追加。#18） |
| `note` | TEXT | 可 | 備考（版数 3 で追加。#18） |
| `created_at` | TEXT | 不可 | 登録日時。一覧はこの順（同時刻は登録した順）に返す |
| `updated_at` | TEXT | 不可 | 更新日時 |

### 3.2 product_history（変更履歴）

ステータスと発売月の推移を記録する。アーカイブから復帰する際に、自動遷移の前のステータスを求めるために使う。

| 列 | 型 | NULL | 制約・説明 |
| --- | --- | --- | --- |
| `id` | INTEGER | 不可 | 主キー（記録した順に増える） |
| `product_id` | TEXT | 不可 | 商品の ID。商品を削除すると履歴も削除する（ON DELETE CASCADE） |
| `changed_at` | TEXT | 不可 | 変更日時 |
| `change_kind` | TEXT | 不可 | `user`（利用者の操作）・`automatic`（自動遷移） |
| `field` | TEXT | 不可 | `status`・`release_month` |
| `value_before` | TEXT | 可 | 変更前の値。登録時は null |
| `value_after` | TEXT | 不可 | 変更後の値 |

記録の規則:

- 登録時: 登録日時に、ステータス → 発売月の順で初期値を記録する（変更前は null、種類は `user`）
- 更新時: ステータス・発売月が変わった場合だけ、ステータス → 発売月の順で記録する。それ以外の項目（メーカー・備考を含む）の変更は記録しない
- 履歴は `id` の順（記録した順）に返す
- ステータスの自動遷移は種類を `automatic` として記録する。リストに戻す・延期の確認への回答は `user` として記録する

### 3.3 delivery_confirmations（延期の確認待ち）

予約済から自動で購入済になり、延期の確認（届いたかどうか）を待っている商品（#9）。アーカイブかどうかは発売月から求めるため保存しない。

| 列 | 型 | NULL | 制約・説明 |
| --- | --- | --- | --- |
| `product_id` | TEXT | 不可 | 主キー。商品の ID。商品を削除すると一緒に削除する（ON DELETE CASCADE） |

記録の規則（[機能設計書](機能設計書.md) BR-02・BR-05）:

- 予約済から購入済に自動遷移したときに追加する（すでにあれば何もしない）
- 延期の確認に回答したとき、リストに戻したとき、編集でステータスを変えたときに削除する

## 4. スキーマの版数と移行

スキーマの版数は SQLite の `PRAGMA user_version` で管理する。移行は `SCHEMA_MIGRATIONS` の要素として定義し、**既存の要素は書き換えず、変更は末尾に追加する**（利用者の既存の DB が壊れるため）。

| 版数 | 内容 | issue |
| --- | --- | --- |
| 1 | `products`・`product_history` を作成 | #7 |
| 2 | `delivery_confirmations` を作成（既存の商品と履歴はそのまま。確認待ちは空） | #9 |
| 3 | `products` に `maker`・`note` を追加（既存の商品は未入力） | #18 |

DB の版数がアプリの版数より新しい場合は、起動を止める（古いアプリで新しい DB を壊さないため）。
